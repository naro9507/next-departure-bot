今回のセッションで行った変更・決定事項をもとに、このプロジェクトのルールドキュメントを更新してください。

## 手順

1. **変更の特定**
   - `git diff HEAD~5..HEAD` や `git log --oneline -10` で直近のコミットを確認する
   - 新しく採用したパターン、変更したアーキテクチャの決定、追加したファイルや技術を洗い出す

2. **`.claude/rules/architecture.md` の更新**
   - 新たに決定したルール・制約があれば追記する
   - 実態と合わなくなった記述を修正する
   - 変更がなければスキップしてよい

3. **`CLAUDE.md` の更新**
   - ディレクトリ構成に新しいファイルが増えた場合は追記する
   - コーディングルールに変更があれば修正する
   - 変更がなければスキップしてよい

4. **コミット & プッシュ**
   - どちらかのファイルを変更した場合のみ、コミットしてプッシュする
   - コミットメッセージ例: `ルールドキュメントを更新 (セッション反映)`

## 注意

- 実装内容そのものは変更しない。ドキュメントだけを更新する
- 些細な変更（typo 修正など）ではルール更新は不要
- 新しいアーキテクチャの判断（技術の追加・変更、設計パターンの導入）があった場合に更新する
